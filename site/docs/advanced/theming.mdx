# Theming

StageRoutine uses a three-tier styling model, moving from broad presentation-wide styles to fine-grained element overrides:

![Styling & Theming Hierarchy](/img/style-layers.svg)

1. **Stage Theming**: Presentation-wide palette set via `stage.theme(...)` across all scenes.
2. **Element Customization**: Local overrides applied directly to an element (`color`, `style`, or container-scoped `theme`).
3. **Built-in Defaults**: Fallback appearance used when no theme or custom style is specified.

## Stage Theming

Call `stage.theme(...)` to apply a color palette across all scenes:

### Using Built-in Themes

StageRoutine includes ready-to-use themes matching popular developer palettes:

```typescript
import { Stage, themes } from "stageroutine";

const stage = new Stage();

// Apply a theme preset:
stage.theme(themes.tokyoNight);
```

Built-in presets include:
- `themes.defaultDark` - Obsidian & cyan (default)
- `themes.defaultLight` - Clean editorial light mode
- `themes.tokyoNight` - Deep navy & neon blue
- `themes.dracula` - Dark violet & pink
- `themes.cyberpunk` - High-contrast black, cyan & yellow

### Creating Custom Themes

To create a custom theme, provide 3 colors (`background`, `text`, and `primary`). StageRoutine automatically derives the matching secondary shades:

```typescript
stage.theme({
  background: "#1e1e2e",
  text: "#cdd6f4",
  primary: "#cba6f7",
});
```

![Automatic Palette Derivation](/img/adaptive-theming.svg)

You can also provide optional overrides for border radius and surfaces:

```typescript
stage.theme({
  background: "#0f172a",
  text: "#f8fafc",
  primary: "#38bdf8",
  radius: "0.75rem",
  surface: "#1e293b",
});
```

## Typography & Custom Fonts

StageRoutine bundles three font families by default using `@fontsource`:

- **Sans-serif (`fontSans`)**: `"Inter"` (weights 400, 500, 600, 700). Default for `Title`, `Text`, `BulletList`, and `Table`.
- **Serif (`fontSerif`)**: `"Newsreader"` (weights 300, 400, italic). Default for `Title({ variant: "serif" })` and emphasized text (`<em>`, `<i>`) inside titles.
- **Monospace (`fontMono`)**: `"JetBrains Mono"` (weights 400, 500, 600). Default for `CodeBlock`, `TerminalBlock`, `Kicker`, and connector labels.

### Using Custom Fonts

StageRoutine presentations are designed to run offline and export to self-contained single-file HTML. Install fonts as `@fontsource` packages so Vite bundles and inlines them directly into your build. Search and preview thousands of open-source fonts at [fontsource.org](https://fontsource.org).

#### 1. Install the font package

```bash
pnpm add @fontsource/plus-jakarta-sans @fontsource/fira-code
```

#### 2. Import the font weights

Import the font weights in your entry file (`src/main.ts`):

```typescript
import "@fontsource/plus-jakarta-sans/400.css";
import "@fontsource/plus-jakarta-sans/700.css";
import "@fontsource/fira-code/400.css";
import "@fontsource/fira-code/600.css";
```

#### 3. Assign the font family in your theme

```typescript
import { Stage } from "stageroutine";

const stage = new Stage({
  theme: {
    fontSans: '"Plus Jakarta Sans", sans-serif',
    fontMono: '"Fira Code", monospace',
  },
});
```

StageRoutine waits for `document.fonts.ready` on startup. Fonts load before layout helpers calculate bounding boxes and connector paths, preventing layout shifts.

### Typographic Scale

StageRoutine scales typography for standard 1080p canvas dimensions. You can customize the scale using font size tokens:

| Token | CSS Variable | Default Value | Target Components |
| :--- | :--- | :--- | :--- |
| `fontSizeHero` | `--sr-font-size-hero` | `6.5rem` | `Title({ variant: "hero" })` |
| `fontSizeTitle` | `--sr-font-size-title` | `3.85rem` | `Title()` |
| `fontSizeLead` | `--sr-font-size-lead` | `2.45rem` | `Title({ variant: "serif" })` |
| `fontSizeBody` | `--sr-font-size-body` | `1.85rem` | `Text()`, `BulletList()`, `Table()` |
| `fontSizeCode` | `--sr-font-size-code` | `1.45rem` | `CodeBlock()`, `TerminalBlock()` body |
| `fontSizeKicker` | `--sr-font-size-kicker` | `1.2rem` | `Kicker()`, `TerminalBlock()` header |

Override scale tokens in your theme configuration:

```typescript
stage.theme({
  fontSizeTitle: "3.2rem",
  fontSizeBody: "1.6rem",
  fontSizeCode: "1.3rem",
});
```

## Element Customization

Elements accept `color`, `style`, and `theme` options.

### Typed Inline Styles

Every element accepts a `style` option typed via `csstype`:

```typescript
import { Title, Text } from "stageroutine";

const title = Title("Architecture Overview", {
  x: "center",
  y: 40,
  color: "#38bdf8",
  style: {
    letterSpacing: "-0.04em",
    textTransform: "uppercase",
  },
});

const body = Text("System design principles...", {
  style: {
    width: "60cqw",
    textAlign: "center",
  },
});
```

### Container-Scoped Themes

You can scope theme tokens to a container or composite component. All child elements inherit the localized theme tokens automatically:

```typescript
import { TerminalBlock } from "stageroutine";

// A custom terminal with its own localized dark palette
const terminal = TerminalBlock({
  title: "zsh",
  theme: {
    surface: "#11111b",
    primary: "#a6e3a1",
  },
});
```

## How Styles Work Under the Hood

### Cascade Layers

StageRoutine wraps all internal component styles inside standard W3C cascade layers:

```css
@layer sr-base, sr-components;
```

1. **`sr-base`**: Declares default `:root` tokens, fonts, and reset styles.
2. **`sr-components`**: Declares component layout and visual styles.

According to the W3C Cascade Layers specification, **unlayered styles always take precedence over layered styles**. This design acts as a defensive sandbox:
- Global CSS resets on a host webpage will not break StageRoutine presentations.
- Custom utility classes applied via `className: "my-class"` always win over default component styles without needing `!important`.

### Semantic Design Tokens

When building custom components, bind colors and metrics to `--sr-*` CSS variables instead of hardcoded values:

| CSS Variable | Default Meaning | Example Usage |
| :--- | :--- | :--- |
| `--sr-background` | Canvas backdrop color | Stage background |
| `--sr-text` | Primary foreground text | Headings, hero copy |
| `--sr-text-muted` | 72% opacity text tint | Paragraphs, descriptions |
| `--sr-text-dim` | 50% opacity text tint | Kickers, labels, bullet dots |
| `--sr-primary` | Main accent / brand color | Focus borders, glow highlights |
| `--sr-surface` | Container background fill | Terminal and Card backgrounds |
| `--sr-surface-border`| Subtle outline | Container edges |
| `--sr-radius` | Global border radius | Cards, buttons, terminals |
| `--sr-font-sans` | Sans-serif typography | Titles, descriptions |
| `--sr-font-serif` | Serif typography | Italic titles, editorial emphasis |
| `--sr-font-mono` | Monospace typography | Code blocks, terminals, kickers |

Referencing these variables ensures your custom elements automatically respond when `stage.theme(...)` is called:

```css
.my-custom-badge {
  background: var(--sr-surface);
  border: var(--sr-surface-border);
  border-radius: var(--sr-radius);
  color: var(--sr-text);
}
```
