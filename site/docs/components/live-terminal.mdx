# LiveTerminal

`LiveTerminal` runs a real command on your machine and streams its output onto the stage. Use it to demo a CLI, narrate a build or test run, or hand the prompt to the audience.

The preview below shows the fallback transcript. A live session needs a running dev server.

<DemoFrame src="/stageroutine/previews/live-terminal.html" />

```typescript preview="live-terminal.html"
// hide-start
import { Stage } from "stageroutine";
const stage = new Stage();
// hide-end
import { LiveTerminal } from "stageroutine";

const deploy = LiveTerminal({
  position: "center",
  width: 150,
  height: 74,
  title: "kubectl -n demo rollout status",
  command: "kubectl -n demo rollout status deploy/api",
  lines: [
    "$ kubectl -n demo rollout status deploy/api",
    "Waiting for deployment \"api\" rollout to finish...",
    "deployment \"api\" successfully rolled out",
  ],
});
// hide-start
stage.scene("Live").with(deploy);
stage.pause();
stage.mount("#stage");
// hide-end
```

A worked deck lives in `examples/terminal` of the repository. Run it with `pnpm --filter terminal-presentation dev`.

## Turning it on

Live sessions are opt in, because they run commands with your user account:

```bash
stageroutine dev --terminal
```

```ts
// vite.config.ts
stageRoutine({ terminal: true });
```

The server accepts connections from the loopback interface only, and every session starts inside your project root. It is never part of a production build.

Each server run also mints a random token. The page fetches it over HTTP and offers it as a WebSocket subprotocol, so a socket from anything else is refused before a process starts. Pass `terminal: { token: "..." }` to pin your own.

## When no server is available

Static builds and `--single-file` exports have no server, and a live session is impossible. Then the element renders `lines` with the same window chrome as [TerminalBlock](./terminal-block), so a deck keeps a readable transcript instead of an empty box. The same happens if the dev server stops.

```ts
LiveTerminal({
  command: "pnpm test",
  lines: ["$ pnpm test", "✓ 42 tests passed in 1.2s"],
});
```

Rows in `lines` are selectable like `TerminalBlock` rows when `interactive` is left at its default.

## Controlling the session

The element exposes the running session:

```ts
const demo = LiveTerminal({ command: "vmstat 1" });

demo.status;        // "idle" | "running" | "exited" | "offline"
demo.send("q");     // type into the process
demo.restart();     // stop it and start a fresh session
demo.focus();       // send keystrokes to the process
```

Set `command` before calling `restart()` to run a different command:

```ts
demo.command = "pnpm build";
demo.restart();
```

The cursor stays steady, including while the terminal has focus.

`restartButton: true` puts the same `restart()` in the window header, where the presenter can
reach it without the console:

```ts
const deploy = LiveTerminal({ rows: 8, restartButton: true, command: "pnpm deploy" });
```

The button stays out of the way elsewhere: it is hidden when the element is showing a transcript
instead of a session, it does not steal keyboard focus, and its click never advances the deck.
Restarting throws the session away, so give `initialInput` when a fresh session should start with
something in it.

A session survives navigation. Walking back to a scene shows the same scrollback, and reloading the page reattaches to the process that is still running. Sessions stop after two minutes without a connected client, and when the dev server stops.

Pass `restartOnActivate: true` for a deck that must replay the same command from a clean screen every time the scene is entered.

## Frames and rows

Size a terminal in rows, the way every other terminal is sized, and the card hugs the grid:

```ts
LiveTerminal({ rows: 13, command: "pnpm release" });
```

Thirteen rows are thirteen rows: the card is as tall as the grid plus its window chrome. Give
`height` in stage units instead and the card keeps that size, so a command that prints two
lines leaves the rest of the frame empty.

A command that is still running fills its rows as it prints. A session that has printed nothing
yet shows an empty frame, so let the deck type into it. `initialInput` runs on every new session,
including one started by the header button:

```ts
const shell = LiveTerminal({
  rows: 11,
  initialInput: "ls -l\n",   // typed once the session attaches
  restartButton: true,
});
```

## Typing during a talk

The terminal only takes over the keyboard after a click, so normal navigation keys keep working. While the prompt has focus, keys go to the process and the deck stays put. Set `autoFocus: true` to focus on scene entry, and `interactive: false` for a display-only terminal.

## Requirements

The server runs commands through [node-pty](https://github.com/microsoft/node-pty), which is an optional dependency. Install it in the project that runs the dev server:

```bash
pnpm add -D node-pty
```

Without it the server reports the missing package, and the element keeps showing its fallback transcript.

The element renders the session with [xterm.js](https://xtermjs.org), which is bundled only in presentations that use it.
