# Core Concepts

StageRoutine is a presentation framework for building continuous presentations, where elements animate smoothly on screen as you advance without discrete slide boundaries.

## 1. Stage

The **Stage** is the presentation engine and canvas. It manages the viewport, runs animations, captures state snapshots, and hosts the visual background.

```typescript
import { Stage, AsciiFluid, vignette } from 'stageroutine';

const stage = new Stage().background(AsciiFluid().decorate(vignette()));
```

After defining scenes and steps, call `stage.mount()` to attach to the DOM and start playback:

```html
<div id="stage"></div>
```

```typescript
// Mount into #stage container (defaults to document.body if omitted)
stage.mount("#stage");
```

- **Persistence**: Elements stay alive across scenes unless removed. When elements move between scenes, they animate to their new positions instead of disappearing.
- **Coordinate System**: Positions are percentages from `(0, 0)` (top-left) to `(100, 100)` (bottom-right). The value `"center"` resolves to `50%`.
- **Anchors (`anchor`)**: Origin alignment point. Defaults to `"top-left"` for text and code blocks, and `"center"` for shapes and headlines.

## 2. Components

**Components** are functions that define markup, default styles, and initial properties. They instantiate styled reactive elements.

StageRoutine includes components for typography (`Title`, `Text`, `Kicker`), containers and shapes (`Card`, `Circle`, `Pill`, `Diamond`), technical graphics (`CodeBlock`, `TerminalWindow`, `Table`, `BulletList`), and diagrams (`Connector`, `SequenceDiagram`).

```typescript
import { Title, CodeBlock } from 'stageroutine';

const title = Title("StageRoutine", {
  x: "center",
  y: 40,
  anchor: "center",
});

const code = CodeBlock(["const answer = 42;"], {
  x: 52,
  y: 24,
  width: "44cqw",
});
```

## 3. Elements & Reactive Properties

**Elements** are component instances. Each element wraps a DOM node with reactive properties:

- **Spatial**: `x`, `y`, `scale` (default: `1`), `rotation` (default: `0deg`), `width`, `height`.
- **Visual**: `opacity` (default: `1`), `color`, `blur` (default: `0px`), `brightness` (default: `1`).

Changing a property animates the element:

```typescript
// Direct assignment (uses default 0.6s quartOut animation)
title.x = 50;

// Fluent transition builder
title.x = to(50).duration(1.2).ease("quartOut");
```

## 4. Scenes

**Scenes** are sections of your presentation (analogous to slides). Declared with `stage.scene("Name").with(...)` to set which elements are visible.

```typescript
stage.scene("Architecture").with(title, code, kicker);
```

Elements included in consecutive scenes stay on screen and smoothly animate to their new positions, while elements not included in the new scene are transitioned out.

## 5. Steps & Pauses

**Steps** define click boundaries (analogous to slide builds). Calling `stage.pause()` groups property changes into a step and saves a state snapshot:

```typescript
// Step 1: Fade in title
title.opacity = to(1);
stage.pause();

// Step 2: Move title to top and reveal code
title.y = to(10);
title.scale = to(0.7);
code.opacity = to(1).when(title, "halfway");
stage.pause();
```

When presenting, playback pauses at each `stage.pause()` until you press Next.

## 6. Motion & Transitions

StageRoutine provides declarative transitions and milestone synchronization:

- **`to(target)`**: Schedules an animated transition (defaulting to `0.6s` with `quartOut` ease).
- **`.when(element, milestone)`**: Chains animations relative to other elements without manual millisecond math (milestones: `"start"`, `"halfway"`, `"end"`).
- **`stagger(elements, properties, options)`**: Cascades property changes across a list.
- **`crossfade(outElement, inElement)`**: Dissolves one element into another.

```typescript
// Animate after title completes
heading.opacity = to(1).when(title, "end");

// Animate halfway through heading animation
body.opacity = to(1).when(heading, "halfway");
```

## 7. Decorators

**Decorators** are helper functions attached via `.decorate()` to add visual styles or effects to elements without changing their layout:

```typescript
import { Title, CodeBlock, gradient, glow, rail, bracket } from 'stageroutine';

const title = Title("StageRoutine").decorate(gradient()).decorate(glow());
const terminal = CodeBlock(["pnpm dev"]).decorate(rail()).decorate(bracket());
```

Built-in decorators include `gradient()`, `glow()`, `rail()`, `bracket()`, and `typewriter()`.

## 8. Backgrounds

**Backgrounds** provide dynamic WebGL or canvas backdrops rendered beneath the stage:

```typescript
import { Stage, AsciiFluid, Starfield, GradientFluid, vignette } from 'stageroutine';

stage.background(AsciiFluid().decorate(vignette()));
```

## 9. Layout

**Layout** helpers organize multiple elements into clean arrangements:

```typescript
import { arrange } from 'stageroutine';

const { rule } = arrange.split([heading, body], codePanel, {
  leftX: 6,
  rightX: 52,
  y: 24,
  gap: 4,
});
```

Available helpers: `arrange.split`, `arrange.stack`, `arrange.grid`, and `arrange.circle`.

## 10. Overlays

**Overlays** are plugins that attach interactive UI on top of the stage. They receive a context with access to the DOM containers, stage dimensions, and the event bus.

```typescript
import { NavigationOverlay, LaserPointer } from 'stageroutine';

stage.overlay(LaserPointer());
stage.overlay(NavigationOverlay());
```

Built-in overlays:

- **`LaserPointer()`** — WebGL laser pointer with glowing trail. Toggle with `L` key or the navigation bar button.
- **`NavigationOverlay()`** — Step and scene navigation buttons that appear on hover near the bottom of the screen.

Custom overlays implement the `OverlayPlugin` interface (`mount`, `show`, `hide`, `destroy`) and communicate through the event bus via `ctx.emit()` and `ctx.on()`.

## 11. Event System

All communication between stage, overlays, keyboard, and the presenter console flows through a single typed event bus. Events use `domain:action` naming:

| Domain | Commands (you send) | Notifications (you receive) |
|---|---|---|
| `nav:` | `nextStep`, `prevStep`, `nextScene`, `prevScene`, `gotoStep`, `gotoScene` | `stepChanged`, `sceneChanged` |
| `stage:` | `requestState` | `resized`, `stateChanged` |
| `pointer:` | `toggle` | `toggled` |

Subscribe and emit from overlays via the context:

```typescript
// Listen for pointer state changes
ctx.on("pointer:toggled", ({ active }) => { /* ... */ });

// Emit a command
ctx.emit("nav:nextStep");
```

The `BroadcastChannel` transparently bridges events to other windows, so the presenter console and overlays share the same event protocol.
